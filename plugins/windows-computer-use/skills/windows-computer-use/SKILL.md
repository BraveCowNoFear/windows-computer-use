# Windows Computer Use

Use the local `windowsComputerUse` MCP to operate Windows directly. It runs in `full-control` mode: it imposes no plugin-owned app allowlist or action confirmation layer. Codex host permissions and Windows integrity boundaries still apply.

## Control stack

Choose the highest reliable layer for each step:

1. Use an application API or browser DOM when already available.
2. Use `inspect_window`, `find_controls`, `invoke`, `perform_secondary_action`, and `enter_text` for UIA3 semantic control. Inspect Value, selection, toggle, expand/collapse, scroll, document-text, and selected-text state instead of inferring it from pixels.
3. Use `wait_for_ui` for control changes and `wait_for_window` for top-level/owned-dialog transitions instead of fixed sleeps. Prefer direct `value_equals`, `value_contains`, `selected`, `unselected`, `toggle_on`, `toggle_off`, `expanded`, `collapsed`, `readonly`, or `editable` predicates when that state is observable. For a custom canvas or other pixel-only transition, pass its fresh screenshot id to `wait_for_visual_change`, then use `wait_for_visual_stable` when the following action requires animation/loading to finish. Treat clocks, video, blinking carets, and unrelated desktop pixels as possible exact-image changes that can also prevent full-frame stability.
4. Use `observe_changes` with the previous `observation_id` when only incremental UIA state is needed; it detects semantic state transitions even when element identity and layout stay unchanged.
5. Use `snapshot` for one atomic window UIA + image observation; use fresh `ocr`/`find_text` for text or `find_image` with a known local template when semantic metadata is missing or incomplete. Use `capture_region` when a known image-relative rectangle should stay actionable or isolate waits from unrelated motion. Pass the observation's `screenshot_id` to crop its exact pixels and omit every selector; omit the id only when intentionally acquiring a fresh window/desktop frame. Use `desktop=true` on fresh `capture`, `capture_region`, `ocr`, `find_text`, or `find_image` when the task depends on visible multi-window or whole-screen state. Keep the default exact 1.0 image scale when dimensions are stable; otherwise supply the narrowest plausible `scale_min`/`scale_max`/`scale_step` range.
6. Prefer semantic/direct Unicode input when it works. When an app specifically requires system clipboard transfer, use `paste_text` for reversible Ctrl+V or `copy_text` for reversible Ctrl+C from the current/all selection. Both restore on success or failure. Use raw clipboard tools only when clipboard state itself must span multiple actions, and read existing clipboard content only when it is relevant.
7. Use `pointer_position`, `move_pointer`, `click`, `mouse_down`, `mouse_up`, `press_key`, `key_down`, `key_up`, `type_text`, `scroll`, or `drag` for physical input fallback. Use the down/up pairs only when a mouse button, modifier, or movement key must remain held across actions; always release it explicitly, while `end_session` remains the cleanup backstop. Keyboard tools should keep an exact window selector by default. Use `desktop=true` only when the current foreground/focus is already intentionally established or for a system shortcut; it preserves that foreground and cannot be combined with a window selector. Prefer `coordinate_space=screenshot` with the same window or virtual-desktop observation's screenshot id. A desktop screenshot action deliberately avoids window selection and foreground activation; use direct `coordinate_space=screen` only when no visual binding is needed. Use `move_pointer` when hover is itself meaningful. Use self-contained `drag` for ordinary left/right/middle/X1/X2 drags and down/move/up for multi-stage CAD or canvas gestures.

Do not delegate to a dedicated UI worker. Drive this MCP directly in the active task.

## Workflow

1. For a window-scoped task, call `list_windows`, select exactly one returned window, and keep its numeric `window_id`; never invent a window object or guess a handle. For a whole-desktop task, start with `observe_desktop` so one call supplies the image, display topology, visible windows, pointer, and actionable screenshot id.
2. Call `display_info` before physical-pixel work when monitor origin, DPI scaling, or cross-display placement matters.
3. Call `inspect_window` or `find_controls`. Prefer a returned stable `control_id` over coordinates.
4. Perform one state-changing action. Use `invoke` for the default/primary action and `perform_secondary_action` for explicit focus, selection membership, toggle, expand/collapse, or semantic scroll. Semantic/input actions activate the target, re-resolve stale elements, and re-observe afterward.
5. Inspect the returned verification. Call `wait_for_window` with the main window's `owner_window_id` when a transient dialog may appear; call `wait_for_ui` with the narrowest semantic state predicate for navigation, saves, progress, selection, toggles, or control-level transitions. Only when no semantic predicate exists, call `wait_for_visual_change` with the last window/desktop screenshot id and, if needed, `wait_for_visual_stable` with the fresh PNG it returns before acting again.
6. Reinspect after a major state change. Treat prior coordinates as stale; control ids can be retried because the broker re-locates their selector.
7. If a broker deadline/transport error says the action state is unknown, do not repeat the action. The MCP has replaced the broker and attempted to release tracked held input; call `list_windows` and re-observe the target first. For an interrupted clipboard action, inspect clipboard state before choosing a recovery step.
8. When a whole-screen visual point is ambiguous, call `window_from_point` on its physical screen coordinate before input; use the returned root `window.id` for UIA or confirm the child HWND/class is the intended native surface. When UIA cannot expose the target, call `find_text` for visible text, `find_image` for a known PNG/JPEG template, `capture_region` for a known sub-image, or `snapshot` for model-side vision. Use bounded multi-scale matching only for expected DPI/zoom variance, not as open-ended image reasoning. Pass the returned image-relative center and `screenshot_id` to `click`, `mouse_down`, `mouse_up`, `scroll`, or `drag` with `coordinate_space=screenshot`. If the broker reports it stale, moved, or resized, observe again instead of retrying blindly.
9. `paste_text` is the default reversible paste transaction. If a multi-action workflow instead uses `write_clipboard_text`, save the `backup_id` immediately and put `restore_clipboard` in a `finally`-style cleanup path. Backup ids are broker-session-local and `end_session` discards any unused ids without changing the current clipboard. Set `preserve_previous=false` only when the requested result intentionally leaves new clipboard content behind.
10. Use `set_window_state` to restore a minimized target before capture, snapshot, OCR, or visual grounding. Use `set_window_bounds` for exact physical-pixel placement/size instead of dragging a title bar; it preserves foreground unless activation is explicitly requested. Minimized visual requests intentionally fail with recovery guidance.
11. Call `end_session` after the Windows phase to clear cached elements and close the control lifecycle.

All coordinates are physical screen pixels. Coordinate tools are window-relative by default and support negative virtual-desktop origins. Ordinary Unicode entry does not mutate the clipboard; explicit clipboard tools do.

The broker shares `codex-ui-control.lock.json` with `desktop-control-for-windows`, so native and legacy fallback actions serialize without extra confirmation prompts.

Read [references/tool-reference.md](references/tool-reference.md) for selectors and exact tool behavior. Read [references/recovery.md](references/recovery.md) when UIA elements disappear, capture is blank, or an app uses a custom canvas.
